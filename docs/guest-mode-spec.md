# 仕様: 未ログインのお試しモード

## Objective

Googleログインを強制せず、初回利用者がすぐに麻雀の記録・成績機能を試せるようにする。
未ログインのデータはブラウザの一時セッションにだけ保存し、クラウド上の永続保存・ルーム共有・別端末からの復元はログイン後に提供する。

## User flow

1. トップページで「ゲストとして始める」を選ぶ。
2. 記録・成績・履歴・設定を通常どおり利用する。
3. 未ログイン中は `sessionStorage` にデータを保存し、ページ更新後は復元する。
4. タブを閉じるとお試しデータは破棄される。
5. 「共有ルームに保存」を選ぶと、未ログインならGoogleログインへ遷移する。
6. ログイン済みならお試しデータを新規共有ルームへ移行し、そのルームを開く。

## Boundaries

- 未ログインのお試しモードでは `POST /api/rooms` を呼ばない。
- 未ログインのお試しデータを `localStorage` やD1へ保存しない。
- 共有ルームURLの作成・参加・別端末共有は従来どおりログイン後に行う。
- JSON書き出しはお試しモードでも利用できる。JSONから共有ルームを作る操作はログイン後に限定する。
- Googleログインが無効な環境では、既存の認証無効ルーム運用を壊さない。公開環境ではGoogleログインを有効にする。

## UI requirements

- トップページに「ゲストとして始める」導線を追加する。
- お試し中は「一時保存」「タブを閉じると消えます」を表示する。
- お試し中に、ログイン後にクラウド保存できる導線を表示する。
- ゲスト開始前、再開可能な状態、ゲスト利用中をそれぞれ区別して表示する。
- Googleログインで新しい共有ルームを作成・保存できることを説明する。
- ログイン後、お試しデータがある場合は保存操作を明示できる。
- クラウド保存に成功したら一時データを消去し、共有ルームへ遷移する。

## Commands

- Test: `npm run test -- src/lib/guest-session.test.ts`
- Check: `npm run check`
- Build: `npm run build`

## Testing strategy

- `guest-session` の読み書き・壊れたデータ・削除を単体テストする。
- 既存の型検査、lint、format、全テストを通す。
- 手動で「利用開始 → 更新 → ログイン → データ保存 → ルーム遷移」を確認する。

## Success criteria

- 未ログインでトップページから記録画面へ入れる。
- お試しデータは更新後に復元されるが、永続DBのルームは作成されない。
- ログイン後にお試しデータを新規共有ルームへ一度だけ移行できる。
- 未ログインの既存共有ルームアクセスは、従来どおり認証要求を表示する。
- `npm run check` と `npm run build` が成功する。

## Open questions

- お試しデータの保持期間はタブのライフサイクル（`sessionStorage`）とする。将来、期限付き保存へ変更する場合は別仕様とする。
