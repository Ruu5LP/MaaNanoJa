# ルーム削除仕様

## Objective

共有ルームの所有者が、設定画面から現在のルームを完全に削除できるようにする。ルーム本体、対局履歴、進行中の半荘、プレイヤー・ルームメンバーの紐付けをまとめて削除し、削除後はルームURLからアクセスできない状態にする。

## Assumptions

- Googleログインが有効な環境では、ルーム所有者だけが削除できる。
- Googleログインが無効な旧運用では、所有者情報がないためルーム削除APIを利用できない。
- 削除は元に戻せないため、設定画面で確認ダイアログを表示する。
- 削除後はルーム選択画面へ戻し、自分のルーム一覧からも消える。

## API

- `DELETE /api/rooms/:code`
- 認証有効時はログイン必須、かつ `room_members.role = 'owner'` のユーザーだけ許可する。
- `rooms` を削除し、外部キーの `ON DELETE CASCADE` により `games` と `room_members` を削除する。
- 成功時は `{ "roomCode": "..." }` を返す。
- ルームがない、または所有者でない場合は、存在を漏らさないため404を返す。

## UI

- 設定タブのデータ欄に、所有者だけ「このルームを削除」ボタンを表示する。
- 削除前に、対局履歴・進行中データを含めて元に戻せないことを確認する。
- 成功後は現在のルームを離れ、ルーム選択画面へ戻る。
- 削除中はボタンを無効化し、失敗時は設定画面にエラーを表示する。

## Testing Strategy

- Worker契約テストで、所有者以外の拒否、所有者の成功、関連行削除SQL、未認証の拒否を確認する。
- クライアントの型チェック・Lint・フォーマット・既存テストを実行する。

## Success Criteria

- 所有者だけが確認操作を経てルームを削除できる。
- 削除後に同じルームコードを取得できず、ルーム一覧からも消える。
- ゲーム、Draft、ルームメンバーのデータが残らない。
- `npm run check` と `npm run build` が成功する。
